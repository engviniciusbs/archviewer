# Compare Versions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Comparar o projeto aberto com um JSON exportado ou com outra pasta, e mostrar as mudanças num painel e no grafo.

**Architecture:** Tudo fica na web. `compare/diff.ts` faz o diff puro entre dois `GraphExport`. `compare/parse.ts` valida JSON externo. `compare/baseline.ts` analisa uma pasta num cliente temporário. O store guarda `comparison`. O modo `colorBy: 'changes'` reaproveita o caminho do heatmap.

**Tech Stack:** React 19, zustand, Vitest, Playwright. Sem mudanças no Rust.

**Spec:** `docs/superpowers/specs/2026-11-09-compare-design.md`

## Global Constraints

- Nenhuma dependência nova e nenhuma mudança no núcleo Rust.
- Cores: `--color-added: #1baf7a` e `--color-changed: #6250d6` (validadas; o aqua precisa de rótulo).
- As listas do painel mostram até 200 itens. Fan-in mostra os 10 maiores.
- Todo texto vai para `en` e `pt-BR`.

## Review Focus

1. **Comparar com um export de outro projeto** (nomes diferentes): o diff funciona e aparece o aviso. Teste na Task 1 (`parseExport` devolve `projectMismatch`) e na Task 3.
2. **Export antigo sem `deadCode`:** a parte de `newlyUnused` fica vazia e o resto não quebra. Teste na Task 1.
3. **Abrir outro projeto durante a análise da pasta de base:** o resultado tardio é descartado, porque a geração mudou. Teste na Task 2.
4. **JSON enorme ou que não é um objeto** (por exemplo, `[]` ou `"x"`): é rejeitado com a mensagem. Teste na Task 1.
5. **Modo "Changes" ativo quando a comparação acaba:** volta a `none`. Teste na Task 2.

### Task 2: comparação no store, pasta de base e modo `changes`

**Files:**

- Modify:

**Interfaces:**
- `Comparison = { label: string; diff: GraphDiff; warning: 'projectMismatch' | null }`
- `ComparePhase = { status: 'idle' } | { status: 'loading'; read: number; total: number } | { status: 'error'; message: string }`
- `compareWithExport(text: string, label: string): Promise<boolean>` devolve `false` quando o JSON é inválido; nesse caso `comparePhase` fica com `{ status: 'error', message: 'invalid' }`.
- `compareWithFolder(source: DirSource): Promise<void>`
- `clearComparison(): void`
- `changesPainter(diff: GraphDiff, colors: { added: string; changed: string }): Paint`
- `changesLegend(t, colors): Legend`

- [ ] **Step 1: testes**
  - **`compareWithExport`:**
    - com o JSON do próprio projeto (o `exportGraph` falso devolve `G1`; o texto é `JSON.stringify(G1)`) resulta em `comparison.diff.changeCount === 0` e `label` igual ao passado;
    - com um JSON inválido devolve `false` e `comparePhase.status === 'error'`;
    - com outro `project`, `warning === 'projectMismatch'`.
  - **`compareWithFolder`:** um `deps.api` que devolve um segundo fake na segunda chamada; o fake de base faz `exportGraph` devolver `G0`. O resultado tem `comparison` preenchido e o `dispose` do fake de base é chamado. Durante a leitura, `comparePhase` passa por `loading`.
  - Abrir outro projeto durante a comparação descarta o resultado.
  - **`clearComparison`:** `comparison` volta a `null`; com `colorBy === 'changes'`, volta a `none`.
  - `setColorBy('changes')` sem comparação não muda nada.
  - **`changesPainter`:**
    - arquivo adicionado recebe a cor `added`;
    - arquivo `from` de uma aresta nova recebe `changed`;
    - grupo `src` com um filho alterado recebe `borderColor: changed`;
    - externo novo recebe `added`.
  - `heatLegend('changes', …)` recebe a legenda de 2 itens.
  - `writeFilters(none, 'changes')` resulta em `''`.
- [ ] **Step 2:** os testes falham.
- [ ] **Step 3:** implementar. O `heatPainter` delega para o `changesPainter` quando `colorBy === 'changes'`; ele recebe `diff` por um parâmetro opcional, e `heatLegend` passa a aceitar as cores `added`/`changed`.
