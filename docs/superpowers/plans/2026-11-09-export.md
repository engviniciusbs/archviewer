# Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adicionar um menu "Exportar" com PNG, SVG, Mermaid (visão atual), JSON completo (projeto inteiro) e badge para README.

**Architecture:** O núcleo Rust ganha `export_graph`, exposto no WASM e no worker. Na web, `src/export/` reúne geradores puros (`mermaid`, `badge`, `svg`, `filename`), um rasterizador de PNG, um registro da cena do Sigma e utilitários de download e cópia. O `ExportMenu` na Toolbar orquestra tudo.

**Tech Stack:** Rust (serde, tsify, insta), React 19, zustand, Sigma 3, graphology, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-09-export-design.md`

## Global Constraints

- Nenhuma dependência nova.
- Nada sai do navegador. A única URL externa é a imagem do shields.io dentro do snippet do badge.
- O JSON é determinístico e não tem `generatedAt`. Os campos são `schema` (`https://archviewer.viniciusbsarmento.com/schema/graph-v1.json`) e `version: 1`.
- Nomes de arquivo seguem o formato `<slug>-archviewer.{png,svg,json}`, com o slug caindo em `project` quando fica vazio.
- Limites: rótulos de arquivo no SVG até 300 nós; aviso de Mermaid acima de 500 arestas; PNG em escala 2; maior dimensão do SVG com 1600 px; margem de 40 px.
- Cores do badge: `2ea043` sem ciclos e `d4a72c` com ciclos. O link aponta para `https://archviewer.viniciusbsarmento.com`.
- Todo texto de interface passa pelos catálogos `en` e `pt-BR`.

## Review Focus

1. **Projeto com nome só de símbolos ou vazio** (`"@@@"`): o nome do arquivo usa `project`. Teste na Task 2.
2. **Rótulos com `"`, `<`, `&`** (por exemplo, a pasta `a&b` ou o arquivo `x"y.ts`): o SVG continua válido (escape XML) e o Mermaid também (escape `#quot;`). Testes nas Tasks 2 e 3.
3. **Grafo com um único nó, ou todos os nós na mesma posição**: o enquadramento não divide por zero e o nó fica centralizado. Teste na Task 3.
4. **Área de transferência ausente** (`navigator.clipboard` indefinido, em contexto inseguro): abre o diálogo de cópia manual. Teste na Task 4.
5. **Exportar enquanto o layout ainda roda**: usa as posições daquele instante, sem erro. Coberto pela leitura síncrona da cena (Task 3); não precisa de teste dedicado.

### Task 3: cena do Sigma, SVG e PNG

**Files:**
- Create: `apps/web/src/export/scene.ts` (tipos `Scene`, `SceneNode`, `SceneEdge`; `sceneFromSigma(sigma, graph)`; `registerSceneSource(fn): () => void`; `currentScene(): Scene | null`)
- Create: `apps/web/src/export/svg.ts` (`buildSvg(scene: Scene, theme: GraphTheme): string`)
- Create: `apps/web/src/export/png.ts` (`svgToPng(svg: string, scale?: number): Promise<Blob>`)
- Modify: `apps/web/src/renderer/GraphCanvas.tsx` (registra a fonte no efeito de criação e remove ao desmontar)
- Test: `apps/web/test/export/svg.test.ts`, `scene.test.ts`

**Interfaces:**
- `SceneNode = { x: number; y: number; size: number; color: string; borderColor?: string; label: string; kind: 'group' | 'file' | 'external' }`
- `SceneEdge = { source: number; target: number; size: number; color: string }`: índices em `nodes`, com as arestas `hidden` já excluídas por `sceneFromSigma`.
- Constantes: `SVG_MAX = 1600`, `SVG_PAD = 40`, `FILE_LABEL_LIMIT = 300`.
- Regra de rótulo:
  - grupos e externos usam o `label` de display;
  - arquivos usam o `label` de display quando `nodes.length <= 300`;
  - acima de 300, só ficam os nós cujo rótulo de display não está vazio **e** que eram destacados (o reducer zera o rótulo dos esmaecidos).

  Para que isso funcione sem ambiguidade, `sceneFromSigma` grava `label: ''` em arquivo acima do limite, a menos que haja seleção e o nó seja o selecionado ou um vizinho, ou seja, que o display data tenha mantido o rótulo enquanto há seleção ativa.
