# i18n (EN/PT) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Interface do ArchViewer em inglês e português, com detecção pelo navegador, seletor persistente e avisos do núcleo estruturados.

**Architecture:** Dicionários tipados em `apps/web/src/i18n` (o `en.ts` é a referência; os outros idiomas usam `satisfies Messages`), um store zustand de idioma e o hook `useT()`. O núcleo Rust troca `Vec<String>` por `Vec<Warning { code, subject }>`, e a web traduz o código.

**Tech Stack:** Rust (serde, tsify), React 19, zustand 5, `Intl.PluralRules` e `Intl.NumberFormat`, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-09-i18n-design.md`

## Global Constraints

- Nenhuma dependência nova.
- Idiomas: `en` (padrão e referência) e `pt-BR`. Os nomes no seletor são "English" e "Português".
- Chave do `localStorage`: `archviewer.locale`. Toda leitura e escrita fica dentro de try/catch.
- Detecção: escolha salva → `navigator.languages` (código exato, depois prefixo) → `en`.
- `<html lang>` segue o idioma ativo; o `index.html` declara `lang="en"`.
- Os textos em `pt-BR` são exatamente os de hoje. Os textos em `en` são a tradução.
- Mensagens técnicas de erro (ingest, analysis, núcleo) ficam em inglês e não passam pelo dicionário.
- Os comentários de código não mudam.

## Review Focus

1. **`localStorage` lança erro** (Safari privado, cookies bloqueados): o app abre com o idioma do navegador e trocar de idioma continua funcionando. Teste na Task 2.
2. **`navigator.languages` vazio ou indefinido**: cai em `en`. Teste na Task 2.
3. **Valor salvo que não é mais um idioma registrado** (por exemplo `es` salvo e depois removido): é ignorado. Teste na Task 2.
4. **`WarningCode` desconhecido em tempo de execução** (WASM mais novo que o bundle em cache): mostra `code: subject` em vez de quebrar. Teste na Task 3.
5. **Trocar de idioma com um painel aberto ou durante o carregamento**: os textos e os números (`1,234` ↔ `1.234`) mudam sem perder estado. Teste na Task 3 (StatusBar com o disclosure aberto).

### Task 2: Base de i18n (dicionários, detecção, formatação, store)

**Files:**
- Create: `apps/web/src/i18n/format.ts`, `detect.ts`, `locales.ts`, `store.ts`, `messages/en.ts`, `messages/pt-BR.ts`
- Modify: `apps/web/src/main.tsx` (nenhuma mudança se o store aplicar o `lang` ao ser importado; ver Step 3), `apps/web/index.html` (`lang="en"`)
- Modify: `apps/web/test/setup.ts` (fixa `en` antes de cada teste)
- Test: `apps/web/test/i18n/format.test.ts`, `detect.test.ts`, `store.test.ts`, `messages.test.ts`

**Interfaces:**
- `format.ts`: `plural(locale: string, n: number, forms: { other: string } & Partial<Record<Intl.LDMLPluralRule, string>>): string` (troca `#` pelo número formatado); `formatInt(locale: string, n: number): string`; `formatSeconds(locale: string, ms: number): string` (uma casa decimal mais `" s"`).
- `messages/en.ts`: `export const en = { … }` e `export type Messages = Widen<typeof en>`, onde `Widen` transforma literais de string em `string` e preserva funções e objetos aninhados.
- `messages/pt-BR.ts`: `export const ptBR = { … } satisfies Messages`.
- `locales.ts`: `export const LOCALES = [{ code: 'en', name: 'English', messages: en }, { code: 'pt-BR', name: 'Português', messages: ptBR }] as const`; `export type LocaleCode = (typeof LOCALES)[number]['code']`; `export function messagesFor(code: LocaleCode): Messages`.
- `detect.ts`: `detectLocale(saved: string | null, languages: readonly string[] | undefined): LocaleCode`; `readSavedLocale(): string | null`; `saveLocale(code: LocaleCode): void`. As duas últimas nunca lançam erro.
- `store.ts`: `useLocaleStore` (zustand) com `{ locale: LocaleCode; setLocale(code: LocaleCode): void }`, que salva e atualiza `document.documentElement.lang`; o estado inicial vem de `detectLocale(readSavedLocale(), navigator.languages)` e o `lang` é aplicado quando o módulo carrega. `useT(): Messages`.

Grupos de chaves do `Messages` (tudo o que é texto hoje nos arquivos listados na Task 3): `fmt` (`int`, `seconds`), `app`, `language` (rótulo do seletor), `toolbar`, `filters`, `search`, `explorer`, `panel` (`show(title)` e `hide(title)`, sem concatenar com `toLowerCase`), `detail`, `importKind`, `snippet`, `status` (um plural por item da barra), `issues`, `skipped`, `reasons` (`UnresolvedReason`), `skipReasons` (`SkipReason | 'unreadable'`), `empty`, `error`, `loading`, `graph`, `warnings: Record<WarningCode, (subject: string) => string>`.

- [ ] **Step 1: testes**
  - `format.test.ts`:
    - `plural('en', 1, { one: '# file', other: '# files' })` → `'1 file'`; com `1234` → `'1,234 files'`;
    - `plural('pt-BR', 1234, { one: '# arquivo', other: '# arquivos' })` → `'1.234 arquivos'`;
    - `formatSeconds('pt-BR', 420)` → `'0,4 s'`; `formatSeconds('en', 420)` → `'0.4 s'`.
  - `detect.test.ts`:
    - `detectLocale('pt-BR', ['en-US'])` → `'pt-BR'`;
    - `detectLocale(null, ['pt-PT', 'en'])` → `'pt-BR'`;
    - `detectLocale(null, ['fr-FR', 'en-GB'])` → `'en'`;
    - `detectLocale(null, [])` → `'en'` e `detectLocale(null, undefined)` → `'en'`;
    - `detectLocale('es', ['pt-BR'])` → `'pt-BR'` (valor salvo inválido é ignorado);
    - com `localStorage.getItem` e `setItem` lançando erro, `readSavedLocale()` → `null` e `saveLocale('en')` não lança.
  - `store.test.ts`: `setLocale('pt-BR')` muda `locale`, grava `archviewer.locale` e define `document.documentElement.lang === 'pt-BR'`.
  - `messages.test.ts`: para cada item de `LOCALES` e cada `WarningCode` (lista literal com os 6 códigos), `messages.warnings[code]('x')` contém `'x'`.
- [ ] **Step 2:** `pnpm --filter @archviewer/web test -- i18n` falha (módulos inexistentes).
- [ ] **Step 3:** Implementar os módulos. `pt-BR.ts` recebe os textos atuais exatamente como estão. `test/setup.ts` chama `useLocaleStore.setState({ locale: 'en' })` num `beforeEach`. `index.html` passa a ter `lang="en"`.
