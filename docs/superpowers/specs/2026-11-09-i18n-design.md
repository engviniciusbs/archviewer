# ArchViewer — Interface em inglês e português (i18n)

- **Data:** 2026-11-09
- **Status:** aprovado em conversa; o usuário dispensou a revisão da spec escrita
- **Subprojeto:** A2 do plano de comunidade (issue #8, roadmap)

## 1. Objetivo

A interface hoje está toda em português, e o README principal agora está em inglês. Quem chega pelo GitHub precisa conseguir usar o app no próprio idioma.

**Critérios de sucesso:**

1. O app abre em inglês ou em português conforme o idioma do navegador (`pt*` → português, qualquer outro → inglês).
2. Um seletor permite trocar o idioma, e a escolha fica salva no navegador.
3. Adicionar um terceiro idioma é copiar um arquivo, traduzir e registrar. O TypeScript aponta qualquer chave faltando ou sobrando.
4. Nenhum texto visível ou anunciado por leitor de tela fica preso a um idioma, incluindo os avisos que vêm do núcleo Rust.

**Fora de escopo:** traduzir comentários de código, idiomas RTL, plataforma de tradução (Weblate/Crowdin), parâmetro de idioma na URL.

## 2. Abordagem

Dicionários tipados, sem biblioteca. `Intl.PluralRules` e `Intl.NumberFormat` cuidam de plural e números. Foram descartados o i18next (≈40 KB, chaves como string, plural exige plugin) e o Paraglide (mais uma etapa de build num pipeline que já compila Rust/WASM). O app tem cerca de 150 textos.

## 3. Estrutura (web)

```
apps/web/src/i18n/
├── messages/
│   ├── en.ts        # referência: exporta `en` e o tipo `Messages`
│   └── pt-BR.ts     # export const ptBR = { … } satisfies Messages
├── locales.ts       # registro: código, nome no próprio idioma, mensagens
├── detect.ts        # idioma inicial: escolha salva → navigator.languages → 'en'
├── format.ts        # plural, inteiros e segundos no idioma ativo
└── store.ts         # zustand { locale, messages, setLocale } + hook useT()
```

- **Mensagens:** objeto aninhado por área (`app`, `toolbar`, `explorer`, `detail`, `snippet`, `status`, `issues`, `screens`, `loading`, `graph`, `reasons`, `warnings`). Texto fixo é `string`. Texto com parâmetro ou plural é função, por exemplo `files: (n: number) => string`.
- **Tipo `Messages`:** é derivado de `en` com as strings alargadas para `string`, de modo que `pt-BR.ts` usa `satisfies Messages` sem precisar repetir os mesmos literais.
- **`plural(locale, n, { one, other, … })`:** escolhe a forma via `Intl.PluralRules(locale)` e troca `#` pelo número formatado com `Intl.NumberFormat(locale)`.
- **Detecção:** primeiro a escolha salva em `localStorage` (chave `archviewer.locale`, leitura e escrita dentro de try/catch); depois cada item de `navigator.languages`, casando o código exato e em seguida o prefixo (`pt-PT` → `pt-BR`); por fim, `en`.
- **`setLocale`:** atualiza o store, salva a escolha e ajusta `document.documentElement.lang`. O `index.html` passa a declarar `lang="en"`, e o idioma detectado é aplicado antes da primeira renderização.
- **Seletor:** um `<select>` compacto na barra superior e na tela inicial, com os nomes dos idiomas escritos no próprio idioma ("English", "Português") e `aria-label` traduzido. As opções vêm de `locales.ts`.
- **`components/format.ts`:** `count`, `seconds`, `REASON` e `SKIP_REASON` saem dali. Os textos vão para as mensagens e a formatação vai para `i18n/format.ts`. `basename` e `message` continuam onde estão.
- **Código fora do React** (`ingest`, `analysis`): os erros técnicos passam a ter mensagens curtas em inglês. A interface mostra uma frase traduzida e acrescenta o detalhe técnico depois dela.

## 4. Contrato de avisos do núcleo

Hoje o núcleo emite avisos como texto em português (`Vec<String>`). Eles passam a ser estruturados:

```rust
#[serde(rename_all = "camelCase")]
pub enum WarningCode {
    ExtendsNotFound,           // extends de tsconfig não encontrado
    InvalidTsconfig,           // tsconfig/jsconfig com JSON inválido
    TsconfigReferenceNotFound, // referência de tsconfig não encontrada
    TsconfigIgnored,           // tsconfig ignorado na resolução (fallback)
    InvalidGlob,               // glob de workspace inválido
    InvalidPackageJson,        // package.json raiz inválido
}

pub struct Warning {
    pub code: WarningCode,
    pub subject: String, // caminho, glob ou escopo citado no aviso
}
```

- `Summary.warnings` e `Issues.warnings` passam a ser `Vec<Warning>`. A deduplicação em `analyzer.rs` continua sendo por valor.
- `AnalyzerError::AlreadyFinished` vira `"analysis already finished"`, uma mensagem técnica.
- O `tsify` gera `Warning` e `WarningCode` em `@archviewer/core-wasm`.
- Na web, `messages.warnings: Record<WarningCode, (subject: string) => string>`. Um código novo no núcleo quebra o typecheck até ganhar texto em todos os idiomas.
- O `StatusBar` deduplica por `code` + `subject`.

## 5. Testes

- **Rust:** a asserção da fixture `broken` e os snapshots `insta` passam a refletir `{ code, subject }`. Cada `WarningCode` ganha um teste que o produz.
- **core-wasm:** o teste de fronteira confere o formato `{ code, subject }`.
- **Web (Vitest):** `test/setup.ts` fixa o idioma `en`, e as asserções existentes passam a usar os textos em inglês. Testes novos cobrem:
  - `detect`: escolha salva, `navigator.languages`, prefixo, fallback e `localStorage` que lança erro;
  - `plural` e números nos dois idiomas;
  - o seletor troca o idioma, re-renderiza a interface e atualiza `<html lang>`;
  - todo idioma registrado tem texto para todo `WarningCode`.
- **e2e (Playwright):** o contexto usa `locale: 'en-US'`. Um passo novo troca para Português e confere "8 arquivos" na barra de status.
